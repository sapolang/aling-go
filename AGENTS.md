# AGENTS.md

## Quick commands

- `make dev` / `wails3 dev` — development mode (hot reload)
- `make build` / `wails3 build` — production build
- `make vet` — `go vet ./...`
- `make test` — `cd frontend && npx tsc --noEmit`
- `make tidy` — `go mod tidy && cd frontend && npm install`
- `make clean` — remove build artifacts
- `wails3 generate bindings -ts` — regenerate frontend Go bindings (TypeScript, output in `frontend/bindings/`, gitignored)

## Architecture

- **Wails v3** (`v3.0.0` stable in `go.mod`).
- Root package (`package main`) is a single slim file `main.go` (~28 lines): it only declares the two `//go:embed` vars (embed cannot reference parent directories, so frontend/dist and build/appicon.png must be embedded from root), the `appVersion` ldflags target, and calls `bootstrap.Run`.
- All startup orchestration (data dir, DB init, service registration, window, tray) lives in `internal/bootstrap`.
- macOS tray template-icon generation (`TrayTemplateIcon`) lives in `internal/system/trayicon.go`.
- Business code is split by domain into 4 packages under `internal/`:
  - `core/` — DB connections (`core.DB` / `core.ArticleDB`), schema DDL, old-data migration, `Init(dataDir)` / `Close()`. Depends on `internal/dict`; must NOT import study/content/system.
  - `study/` — learning side: `WordService` (words/tags/SRS/stats + SQL in `words_store.go`), `FavoriteService`, `DictService`, DTOs in `models.go`.
  - `content/` — input side: `ArticleService` (+ `article_store.go`), `LibraryService`, `MediaService`, `WhisperService`, `ffmpeg.go`, DTOs in `models.go`.
  - `system/` — infrastructure: `PlatformService`, `BackupService`, `AIService` (`translate_service.go`), tray icon helper (`trayicon.go`).
  - `dict/` — read-only ECDICT dictionary (pre-existing, independent).
  - Add new code to the matching domain package; create a new package only when a domain grows large and self-contained.
- Startup flow inside `bootstrap.Run`: resolve data dir → `core.Init(dataDir)` (opens 3 SQLite DBs + migrations) → `application.New()` → register 10 services from study/content/system → create window + tray → `Run()` → `core.Close()` (deferred)
- DB init & migration happen inside `core.Init` before `application.New()`, not in `ServiceStartup`.
- All Go ↔ frontend data exchange uses manual `json.Marshal`/`json.Unmarshal` on JSON strings.

## Data layer

- Three SQLite databases in `os.UserConfigDir()/aling-go/`:
  - `userData.db` — words, tags, SRS, typing progress (`core.DB`)
  - `articles.db` — read-only articles/categories (`core.ArticleDB`)
  - `dict.db` — read-only dictionary (`internal/dict/`, `var dictDB *sql.DB`); opened via `dict.OpenDictDB(dataDir, core.DB)` from `core.Init`
- Business packages access the DBs only through the exported `core.DB` / `core.ArticleDB` handles (package-level globals inside `core`); `dictDB`/`userDB` are globals in `internal/dict`
- Media library uses `library.json` (not SQLite) stored in the config dir

## Bindings gotcha

Bindings are `.ts` files generated by `wails3 generate bindings -ts` into `frontend/bindings/` (gitignored). Services live in 3 packages, so the bridge imports paths like `../../bindings/aling-go/internal/study/wordservice` (also `internal/content/...`, `internal/system/...`). Binding Call IDs embed the package path, so any package move requires regenerating bindings AND updating `frontend/src/api/bridge.ts` (the only frontend file that imports bindings directly; everything else goes through `window.api`). The `@wailsio/runtime` npm package (official, `^3.0.0`) provides the JS runtime — do not reintroduce a local shim.

## Gotchas

- `findFFmpeg` and `extractAudio` in `internal/content/ffmpeg.go` are package-level, shared by `MediaService` and `WhisperService` (both must stay in `content`)
- `bundleResources()` in `internal/content/whisper_service.go` called by `findFFmpeg` (macOS .app bundle path resolution)
- DTOs live next to their domain (`study/models.go`, `content/models.go`); `core` intentionally has no business types to keep the dependency direction one-way
- `appVersion` must stay in `package main` (declared in `main.go`): build Taskfiles inject via `-X main.appVersion=...`; the anchor is package path + variable name, not the file name. `main.go` passes the value to `system.NewPlatformService`
- `wails3` CLI must be installed separately: `go install github.com/wailsapp/wails/v3/cmd/wails3@latest`
- No Go unit tests exist yet
- `.task/` directory is build cache (gitignored), created by Wails internal task runner
